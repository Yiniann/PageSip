# PageSip 项目规划

创建日期：2026-10-20

## 1. 产品目标

帮助读者沉浸阅读日语和英语原文小说。用户导入自己的文本后，可以点击单字、单词，或选择短语、整句，在底部抽屉内查看 AI 给出的上下文解释。

核心流程：导入 → 进入书架 → 阅读 → 点击字词 → AI 解释 → 继续阅读。

## 2. 用户已确认的需求

- 产品名称为 PageSip，取意 Page（书页）与 Sip（小口品味）。
- 通过导入功能加入文章或书籍。
- 日语、英语都需要支持。
- 点击字词后出现底部抽屉，提供翻译与解释，结合上下文。
- 使用 AI 实现解释，不接入词典作为查词方案。
- 三端指电脑网页、手机和平板；不是预先指定三个操作系统。
- 希望使用 Tauri、React；用户提出 Node.js，但是否需要后端需要由架构决定。
- 后续希望支持段评。

以下架构及范围为建议方案，后续可结合验证结果调整。

## 3. 建议架构

| 模块 | 技术方向 | 职责 |
| --- | --- | --- |
| 客户端界面 | React + TypeScript + Vite | 响应式书架、阅读器、底部抽屉 |
| 应用封装 | Tauri 2 | 原生文件能力与应用安装包 |
| 阅读核心 | 独立 TypeScript 模块 | 内容解析、文本定位、上下文和进度 |
| 网页存储 | IndexedDB | 导入内容、元数据、进度和缓存 |
| 原生存储 | 通过存储接口适配；SQLite 为候选 | 避免界面依赖平台专属数据库 |
| AI 服务 | Node.js + TypeScript | 模型调用、密钥、流式响应、用量管理 |

React 网页必须能够独立运行，界面不直接依赖 Tauri API。导入、存储与平台能力通过适配接口调用。

Node.js 建议作为部署在服务器上的轻量 AI API，而不是在手机和平板内启动本地 Node 进程。Tauri 原生层保留必要的 Rust 代码。

本地导入和阅读无需云端书库。使用平台统一提供的 AI 时，模型密钥放在服务器。首版 AI 供应商、模型与服务端框架尚未选择。

参考资料：

- https://v2.tauri.app/start/
- https://v2.tauri.app/start/frontend/
- https://v2.tauri.app/learn/sidecar-nodejs/

## 4. 建议的 MVP

| 模块 | 包含内容 |
| --- | --- |
| 导入 | TXT、无 DRM 的文字型 EPUB；识别或手动设置语言 |
| 书架 | 标题、封面、最近阅读、进度、删除 |
| 阅读 | 目录、滚动阅读、字号、行距、主题、自动恢复进度 |
| AI 理解 | 点击字词、手动选区、语境释义、读音、原形、语法、整句翻译 |
| 收藏 | 保存词句、所在上下文和解释 |
| 三端适配 | 电脑网页、手机、平板的布局及输入交互 |

暂缓：PDF/OCR、复杂固定版式、日语竖排、账号与云同步、公开段评、朗读和学习统计。

手机和平板的系统、浏览器及原生安装包交付范围需要进一步确定；不能把响应式网页等同于完成所有原生系统适配。

## 5. 点击与解释

### 英语

先基于文本边界定位点击的单词，再由 AI 判断当前语境中的表达。用户可手动选择固定搭配或整句。

### 日语

先记录点击的字及其位置，再让 AI 结合当前句判断完整表达。无需预先对整本书进行 AI 分词，也不引入词典完成释义。

### 手动选区

用户明确选择的范围优先于自动选词，允许查询单字、短语和整句。

### 抽屉内容

1. 目标表达与读音，必要时显示原形。
2. 此处含义，优先回答用户当前的问题。
3. 词形、语法、语气或固定搭配说明。
4. 默认折叠的整句翻译。
5. 收藏、调整范围及重新解释。

打开与关闭抽屉需要保持正文位置；目标表达保持高亮。支持触摸手势、鼠标与键盘关闭操作。

## 6. AI 上下文与结果约束

- 请求包含目标文本、点击位置、当前句与适量已读前文。
- 允许主动扩大上下文，默认不发送整本书或后续章节。
- 日语和英语默认以中文解释；读音等字段按语言处理。
- 将小说原文作为待分析数据，与服务指令分离。
- 使用结构化结果，客户端验证字段及原文范围；返回的选区必须与原文相符并覆盖点击位置。
- 明确文本偏移的计数规则，处理 Unicode、日语注音以及显示文本与源文本的映射。
- 上下文不足时允许模型说明不确定性，不强行补全人物关系和省略信息。

流式响应时先展示可用释义，结构化选区经过校验后再应用到正文。模型输出不直接作为可信 HTML 渲染。

## 7. 响应与成本

- 点击后立即显示抽屉与加载状态；优先返回简短释义。
- 快速切换目标时取消旧请求或忽略过期结果，防止解释串词。
- 以点击触发调用，首版不预翻译整章。
- 缓存包括目标位置、上下文摘要哈希、语言、模型标识及提示版本；不能仅按单词缓存。
- 断网仍可阅读本地书籍和已缓存解释；新请求失败时提供重试。
- 统一密钥放在服务端；对外开放 AI API 前加入必要的鉴权和用量限制。

## 8. 内容与数据定位

建议结构：书籍版本 → 章节 → 段落 → 文本范围。

主要数据对象：

- Book / BookVersion：书籍元数据、来源指纹及解析版本。
- Chapter / Paragraph：稳定标识、规范化文本及渲染映射。
- ReadingPosition：版本、章节、段落与文本偏移。
- ExplanationCache：请求上下文标识与 AI 解释。
- SavedPassage：收藏原文、位置、上下文及解释。
- ReaderSettings：语言、主题与排版。

定位同时保留文本摘录和相邻文本，便于恢复与校验。不要用页码或 DOM 序号作为唯一定位依据。

段评先保证同一导入版本内的定位。跨版本公开段评需要额外的版本识别和段落匹配，不假定不同 TXT/EPUB 天然共享段落标识。

## 9. 开发里程碑

### 阶段一：核心技术验证

- [ ] 跑通独立 React 网页和最小 Tauri 应用。
- [ ] 用少量日语、英语样本文本验证点击与手动选区。
- [ ] 接入 AI，验证日语自动确定表达、英语固定搭配与语境解释。
- [ ] 验证底部抽屉及快速切词时的请求一致性。
- [ ] 验证 EPUB 注音、长章节性能和触摸选区；据此选择解析及渲染方案。

验收：在目标设备样例中，点击后选中正确文本并返回相符解释，关闭抽屉后阅读位置稳定。

### 阶段二：本地阅读闭环

- [ ] TXT/EPUB 导入与内容规范化。
- [ ] 书架、目录、阅读排版、进度恢复。
- [ ] 网页本地存储及备份导出设计。
- [ ] 导入 EPUB 时清理脚本、事件处理器和不需要的远程资源。

验收：能够导入并连续阅读一本书，关闭重开后恢复位置；大书按章节加载，不一次渲染整本书的字词节点。

### 阶段三：AI 完整体验

- [ ] Node.js AI 接口与模型适配接口。
- [ ] 上下文提取、结构校验、流式显示、缓存及失败重试。
- [ ] 词句收藏。
- [ ] 用量记录及服务开放所需的访问控制。

验收：导入、阅读、解释、收藏形成闭环；切换词语不串结果，同词不同语境不误用缓存。

### 阶段四：三端完善

- [ ] 电脑、手机、平板实际设备检查。
- [ ] 触摸、横竖屏、键盘、安全区域与抽屉遮挡处理。
- [ ] 按目标系统验证原生导入、存储和应用生命周期。
- [ ] 根据确定的交付范围准备 Tauri 安装包。

验收：目标设备均能稳定导入、阅读和查询；明确区分已验证的网页与原生包范围。
